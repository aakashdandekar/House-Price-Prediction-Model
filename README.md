# House Price Prediction

A linear regression model that estimates house prices from four property features: floor area, number of rooms, age of the building, and distance to the city. This repository documents the full workflow (data inspection, cleaning, training, evaluation, and model serialization) and provides a trained model artifact for reuse.

## Overview

The project addresses a supervised regression task: given a house's size, room count, age, and distance from the city, predict its sale price. Linear regression was chosen as a transparent, fast baseline. It is intended for analysis, teaching, and as a benchmark against more complex models. It is not yet validated for production pricing decisions.

## Data Card

### Source and Provenance

The dataset is a tabular file of house records. Its origin and collection method are not documented in the repository. Before using the model for any decision, confirm that the data is representative of your target market and that you have the right to use it.

### Schema

| Column | Type | Unit | Observed range (raw) | Description |
|---|---|---|---|---|
| `square_feet` | float | square feet | 500 to 3,963 | Living area |
| `num_rooms` | integer | count | 2 to 7 | Number of rooms |
| `age` | integer | years | 0 to 99 | Age of the house |
| `distance_to_city(km)` | float | kilometres | 1.0 to 29.99 | Distance to the city |
| `price` | float | currency (unspecified) | -95,613 to 660,168 | Target variable |

### Quality Checks

- No missing values in any column.
- All features are numeric, so no categorical encoding is required.
- The raw `price` column contains negative values and values above 600,000 that are not plausible sale prices. These rows are excluded during cleaning.
- The currency of `price` is not specified in the source data.

### Cleaning Rules

| Rule | Rows removed |
|---|---|
| `price` greater than 600,000 | 4 |
| `price` less than 10,000 (includes all negative prices) | 55 |

After cleaning, 9,941 rows remain. These thresholds were chosen by inspecting this dataset and are not based on external market data.

## Model Card

### Model Details

- **Type:** Ordinary least squares linear regression (scikit-learn `LinearRegression`)
- **Target:** `price`
- **Features:** `square_feet`, `num_rooms`, `age`, `distance_to_city(km)`
- **Artifact:** `model.pkl`, serialized with joblib

### Intended Use

Educational use, exploratory analysis, and as a baseline for comparison with other regression models.

### Out-of-Scope Use

- Setting or appraising real property prices
- Financial, lending, or insurance decisions
- Any application where the data does not match the population described in the Data Card

### Evaluation

Evaluation uses a single 85/15 train-test split with `random_state=42`. The test set contains 1,492 rows.

| Metric | Value |
|---|---|
| R² (coefficient of determination) | 0.955 |
| Root mean squared error (RMSE) | approximately 20,200 |

The fitted model has these approximate coefficients, in the units of the features:

| Feature | Effect on price |
|---|---|
| `square_feet` | about +150 per square foot |
| `num_rooms` | about +20,100 per room |
| `age` | about -1,000 per year |
| `distance_to_city(km)` | about -5,000 per kilometre |

The near-linear fit and high R² are unusually strong for real estate data. The dataset may be synthetic or heavily processed. Performance on real-world data is likely to be lower.

### Ethical and Fairness Considerations

The dataset has no location, neighbourhood, or demographic fields, so the model cannot directly encode those attributes. However, distance to the city and other features may act as proxies for socioeconomic factors. Any use that affects people should include a fairness review.

## Methodology

1. **Load.** The notebook prompts for the dataset path and reads it with pandas.
2. **Inspect.** Column types, null counts, and summary statistics are checked, and price is plotted against room count.
3. **Clean.** Rows with implausible prices are removed (see Cleaning Rules).
4. **Prepare features.** The target is separated from the features. One-hot encoding is applied as a no-op for this dataset because all columns are numeric.
5. **Split.** 85% of rows go to training and 15% to testing, with a fixed random seed.
6. **Train.** A `LinearRegression` model is fitted on the training set.
7. **Evaluate.** R² is computed on the held-out test set.
8. **Persist.** The model is saved as `model.pkl`.

### Why Linear Regression

- **The target is continuous.** Price is a numeric value, which makes this a regression problem.
- **The relationships look roughly linear.** Each feature has a steady effect on price, which suits a linear model.
- **The model is interpretable.** Each coefficient shows the change in price for a one-unit change in a feature, holding the others constant.
- **It is fast and simple.** Training takes a fraction of a second and needs little tuning.
- **It is a baseline.** More complex models should be compared against it to show whether the added complexity is justified.

The main limitation is that linear regression cannot capture non-linear effects or feature interactions (for example, a room may add more value in a city centre than in the suburbs) unless those are engineered manually.

## Environment and Dependencies

The project uses Python 3 and these libraries:

- pandas (data loading and manipulation)
- scikit-learn (model training and evaluation)
- joblib (model serialization)
- seaborn and matplotlib (plotting)
- Jupyter Notebook, JupyterLab, or Google Colab (to run the notebook)

Exact library versions are not pinned in this repository. For reproducibility, record the versions you used (for example, with `pip freeze`) and keep them with the model artifact.

## Reproducing the Results

1. Clone the repository.
2. Install the dependencies listed above.
3. Open `house_price_prediction.ipynb` in Jupyter or Google Colab.
4. Run all cells in order. When prompted for the dataset, enter `house_prices_dataset.csv` or the path to your copy.
5. Confirm that the test R² is approximately 0.955. Small differences can occur across library versions.

The fixed random seed (42) makes the split reproducible for the same data and library versions.

## Using the Trained Model

Load `model.pkl` with joblib and call `predict` on a table with the four feature columns, in the same order used in training: `square_feet`, `num_rooms`, `age`, `distance_to_city(km)`. The model returns predicted prices in the same currency unit as the training data.

Load the model only in environments where you trust the file, and with a scikit-learn version compatible with the one used to save it.
